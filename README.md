# Астро-Волга — сайт и личный кабинет агента

Локальный сервис на Node.js и PostgreSQL. Node.js раздаёт хаб и девять городских страниц, принимает заявки на обратный звонок и предоставляет агентам защищённый личный кабинет.

## Что реализовано

- кнопка «Оставить заявку» только в карточках агентов с активным кабинетом;
- форма с именем, телефоном и обязательным согласием на обработку данных;
- отдельная очередь заявок для каждого агента;
- вход по логину и паролю, серверные PostgreSQL-сессии, CSRF-защита и ограничение частоты запросов;
- статусы заявки: «Новая», «В работе», «Обработанные», «Отказ»;
- уточнение деталей в отдельном окне: причина и дата переноса, оказанные услуги или комментарий отказа;
- автообновление кабинета каждые 15 секунд;
- пароли хранятся только как bcrypt-хеши.

## Требования

- Node.js 20 или новее;
- PostgreSQL 14 или новее;
- npm.

## Первый запуск

Установите пакеты:

```bash
npm install
```

Создайте пользователя и базу PostgreSQL. Один из вариантов через `psql`:

```sql
CREATE USER astro_volga WITH PASSWORD 'замените_пароль';
CREATE DATABASE astro_volga OWNER astro_volga;
```

Создайте локальную конфигурацию и сгенерируйте секрет сессии:

```bash
cp .env.example .env
openssl rand -hex 32
```

Впишите полученную строку в `SESSION_SECRET`, а пароль от PostgreSQL — в `DATABASE_URL` файла `.env`. Затем выполните миграцию и запустите приложение:

```bash
npm run db:migrate
npm start
```

Сайт откроется по адресу `http://127.0.0.1:4174`, личный кабинет — `http://127.0.0.1:4174/agent/`. Файлы нельзя открывать через `file://`: формы и кабинет работают только через Node.js-сервер.

## Создание кабинета агента

Пароль передаётся через переменную окружения и не сохраняется в файлах проекта:

```bash
AGENT_PASSWORD='надёжный-пароль-агента' npm run agent:create -- \
  --login agent-berd-01 \
  --name 'Агент на ул. Победы' \
  --city berdyansk \
  --address 'ул. Победы, 15' \
  --phone '+7 (990) 000-00-00'
```

Доступные ключи основных городов: `berdyansk`, `energodar`, `kamenka`, `melitopol`, `primorsk`, `tokmak`, `vasilevka`, `veseloe`, `znamenka`.

Адрес и телефон должны совпадать с данными карточки на городской странице. После команды кабинет активируется, а кнопка обратного звонка появится у соответствующей карточки. Повторный запуск с теми же городом, адресом и телефоном обновляет логин, имя и пароль.

Отключить кабинет и убрать кнопку из карточки можно командой:

```bash
npm run agent:disable -- --login agent-berd-01
```

При следующем запросе активная сессия отключённого агента будет завершена.

## Проверка работающего API

Для сквозной проверки можно временно создать тестовый кабинет и выполнить:

```bash
SMOKE_LOGIN='логин' \
SMOKE_PASSWORD='пароль' \
SMOKE_AGENT_NAME='отображаемое имя' \
npm run test:smoke
```

Тест проверяет health API, публикацию агента, создание заявки, вход, получение заявки, смену статуса и выход. Созданную тестовую заявку после проверки необходимо удалить из базы.

## Docker Compose (необязательно)

Перед запуском замените `change_me` и `SESSION_SECRET` в `docker-compose.yml`, затем выполните:

```bash
docker compose up --build
```

Для локального HTTP оставьте `COOKIE_SECURE=false`. При публикации за HTTPS-прокси установите `COOKIE_SECURE=true`, используйте отдельные секреты и не публикуйте PostgreSQL-порт наружу.

## Структура сервиса

- `server/app.js` — API, сессии, защита и раздача сайта;
- `server/sql/` — схема и миграции PostgreSQL;
- `server/create-agent.js` — создание и обновление кабинетов;
- `agent/` — интерфейс личного кабинета;
- `berdyansk/berdyansk.js` — общая логика городских страниц и формы обратного звонка;
- `.env.example` — шаблон локальной конфигурации без секретов.

В репозиторий нельзя добавлять `.env`, реальные пароли и дампы базы данных.
